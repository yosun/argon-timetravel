## 1. Executive Summary & Project Purpose

**TIME TRAVEL** is an autonomous 3D world authoring engine, closed-loop 4-view adversarial critic, and counterfactual multi-century causal simulator. It is designed to take single uncalibrated 2D photographs of historical architecture or interior environments, recover metric 3D camera geometry and floorplans using **MoGe-2 monocular depth**, autonomously author unrestricted procedural 3D scenes via **Blender 4.1 (`bpy`)** guided by **Gemini 4 Argon**, audit the reconstruction with an independent **4-View Adversarial Critic**, and simulate branching architectural counterfactuals across historical eras (e.g., 1206 Romanesque, 1566 Renaissance renovation, 1938 War preservation, and 2026 Alternate Present).

This document captures the complete architectural, algorithmic, and operational context required for **Codex Cloud** to continue development seamlessly without repeating completed work.

## 3. Coordinate System & Space Transformations

A key architectural rule is ensuring strict metric alignment between Three.js camera space and Blender world space:

* **Three.js Metric Camera Space**:
  * Origin `[0.0, 0.0, 0.0]` is the camera optical center.
  * `+X` = Right (meters)
  * `+Y` = Up (meters)
  * `-Z` = Forward looking into the scene (meters)
  * Ground plane elevation: `Y_ground ≈ -1.72m` (calibrated by MoGe-2 for standard standing eye-height ~1.7m).
* **Blender World Space (`bpy`)**:
  * `+X` = Right
  * `+Y` = Forward (into scene)
  * `+Z` = Up (elevation)
* **Transform Functions** (defined in `blender_toolchain.py` and strictly preserved):
  ```python
  def three_to_blender(x: float, y: float, z: float):
      return (float(x), float(-z), float(y))

  def blender_to_three(bx: float, by: float, bz: float):
      return (float(bx), float(bz), float(-by))
  ```
* **GLTF 2.0 Export**: Exported with `export_yup=True`, ensuring exported `.glb` models drop into Three.js at exact 1:1 scale and orientation without matrix adjustment.

## 4. API Specification & Endpoints

All endpoints are hosted by `server.js` on port `3456`:

### 1. `GET /api/status`
Returns service health, active Vertex AI project (`crueltycam`), model ID (`gemini-4-argon`), and backend engine status.

### 2. `POST /api/depth`
* **Input**: `{ imageDataUrl: string, gridWidth: 192, gridHeight: 168 }`
* **Output**: Metric depth grid, 3D point cloud, camera intrinsics (FOV 98.79°, `fx`, `fy`, `cx`, `cy`), normal map, confidence map, and GLTF mesh path.

### 3. `POST /api/argon/mvp3-author`
* **Input**: `{ imageDataUrl, gridOverlayDataUrl, metricSummary, thinkingLevel: "LOW"|"MEDIUM"|"HIGH" }`
* **Behavior**: Round 1 unrestricted 3D authoring. Gemini 4 Argon writes native Python `bpyCode` based on the photograph and MoGe-2 metric coordinates.
* **Blender Output**: Generates `.glb`, compiles telemetry (vertex count, bounding boxes, ground elevation delta), and caches under `.cache/mvp3_r1_*`.

### 4. `POST /api/argon/mvp3-critic`
* **Input**: `{ originalImageDataUrl, fourViews: { originalCam, threeQuarter, lowAngle, wireframe }, bpyCode, blenderTelemetry, roundNumber }`
* **Behavior**: Evaluates 4 actual rendered viewpoints against the original photo. Produces structured critique JSON:
  * Overall alignment score (0–100)
  * Sub-scores: Perspective Alignment, Ground Contact, Proportions, PBR Realism
  * Geometric flaws with specific fix recommendations
  * Rewritten `repairedBpyCode` (for Round 2).

### 5. `POST /api/argon/mvp3-rewrite`
* **Input**: `{ originalImageDataUrl, round1BpyCode, critique, metricSummary }`
* **Behavior**: Closed-loop code rewrite applying critic findings. Compiles the repaired scene in Blender 4.1 and verifies metric improvements.

### 6. `POST /api/argon/mvp3-causal` & `POST /api/argon/mvp3-causal-stream`
* **Input**: `{ originalImageDataUrl, verifiedBpyCode, interventionText, metricSummary }`
* **Behavior**: Multi-epoch counterfactual causal simulation. Emits 4 epochs (1206, 1566, 1938, Alternate 2026).
* **Streaming Protocol**: `/api/argon/mvp3-causal-stream` uses newline-delimited JSON (`application/x-ndjson`) emitting real-time events:
  * `{ phase: "plan", eras: [...] }`
  * `{ phase: "era_compile_start", year: 1206 }`
  * `{ phase: "era_compiled", year: 1206, glbUrl: "...", objectCount: 42 }`
  * `{ phase: "done", payload: {...} }`

### 7. `GET /api/progress` & `POST /api/progress/save`
Stores and retrieves milestone screenshots, telemetry, and acceptance validation runs in `progress.json`.

## 8. Transitioning to Codex Cloud: Environment & Dependency Guide

When moving from local macOS to a Linux-based **Codex Cloud** container, note the following environment differences and setup steps:

### 1. Headless Blender Configuration
* **Local Mac**: Uses `/Applications/Blender.app/Contents/MacOS/Blender`.
* **Codex Cloud (Linux)**: Blender executable is typically located at `/usr/bin/blender` or installed from official binaries.
* **Configuration in `server.js`**: `server.js` checks for `BLENDER_PATH` in environment variables before falling back to the Mac default:
  ```javascript
  const BLENDER_BIN = process.env.BLENDER_PATH || (
    process.platform === 'darwin'
      ? '/Applications/Blender.app/Contents/MacOS/Blender'
      : 'blender'
  );
  ```
  In Codex Cloud, ensure `blender` is in `PATH` (e.g. `sudo apt-get install -y blender` or download Blender 4.1+ for Linux), or export `BLENDER_PATH=/path/to/blender`.

### 2. Google Vertex AI / Gemini API Credentials
* **Local Mac**: Uses `gcloud auth print-access-token` for project `crueltycam`.
* **Codex Cloud**: Configure Vertex AI authentication using either:
  * Service Account JSON: `export GOOGLE_APPLICATION_CREDENTIALS="/path/to/key.json"`
  * Or export `GEMINI_API_KEY` / Cloud access token.

### 3. MoGe-2 Depth Estimation Credentials
* For live depth calculation of new photographs, set:
  ```bash
  export AI3D_API_KEY="your-ai3d-api-key"
  ```
* For existing benchmark photographs (e.g. `cloister_courtyard.jpg`, `living_room.jpg`), the system runs fully offline with zero external network requests using pre-computed responses.

### 4. Zero-NPM Guarantee
* No `npm install` is needed for external packages. The server runs strictly on Node.js core libraries (`http`, `https`, `fs`, `path`, `crypto`, `child_process`).

## 9. Key Architectural Decisions (ADRs)

1. **ADR-1: Zero External NPM Dependencies**
   * *Decision*: Avoid npm dependencies like `express` or build bundlers (`webpack`, `vite`).
   * *Rationale*: Guarantees instant startup in any container or cloud workspace with zero version mismatch or install failures.

2. **ADR-2: Unrestricted `bpy` Generation Over Rigid Templates**
   * *Decision*: Allow Gemini 4 Argon to write full Python scripts for Blender rather than choosing from predefined scene parameters.
   * *Rationale*: Enables handling any unseen architectural style (Gothic, Romanesque, Brutalist, Baroque) without engineering custom schemas for every building type.

3. **ADR-3: Independent 4-View Adversarial Art Director Critic**
   * *Decision*: Never trust single-view depth or initial generation. Render four actual camera perspectives (Original, 3/4 Overview, Low Ground Contact, and Wireframe) and critique them independently before accepting the world.
   * *Rationale*: Resolves the classic 3D hallucination problem where models look plausible from the front camera but float or distort in true 3D space.

4. **ADR-4: Continuous Draggable Timeline with Non-Destructive Causal History**
   * *Decision*: Store alternate histories in `state.branches` (`orig`, `branchA`, `branchB`) and enable smooth temporal scrubbing across eras.
   * *Rationale*: Enables instant comparative counterfactual analysis without losing earlier simulation runs.

5. **ADR-5: Streaming NDJSON Progress for Multi-Epoch Compilation**
   * *Decision*: Use `/api/argon/mvp3-causal-stream` with newline-delimited JSON.
   * *Rationale*: Multi-century procedural compilation takes several seconds per era in Blender. Streaming provides instantaneous feedback as each epoch is completed.

1. **Milestone 4: Interactive Branching Causal Graph UI**
   * Visual DAG / branching decision tree in the UI showing the causal split points.
